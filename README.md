# AgroSupport (AAIAP) Android v0.2.1

Android-приложение на Kotlin, внутри которого работает сайт AAIAP v0.2.1 (WebView).
Проект открывается в Android Studio целиком: **File → Open → папка `AgriSupport-Android-r7`** (где лежит `settings.gradle.kts`).

## Архитектура
- `app/src/main/assets/` — сайт целиком (index.html, styles.css, map.css, **mobile.css**, js/, assets/). Лежит внутри приложения.
- `MainActivity.kt` — оболочка: WebView, заставка, экран загрузки, экран ошибки, баннер «нет интернета», кнопка «Назад», выбор файла (GeoJSON, фото), безопасные настройки.
- `ApiBridge` (в том же файле) — заменяет Python-сервер `server.py`: отдаёт встроенные данные (точка Nebraska, пустой список фото) и, если задан адрес сервера, пересылает ему запросы на данные.
- Сайт открывается по виртуальному адресу `https://appassets.androidplatform.net/`, поэтому работают модули JS, localStorage (язык, тема, расчёты) и относительные ссылки. Доступ к `file://` выключен, мост JS→Android не создаётся.
- `dark-theme.css` — тёмная тема v2: оформлена в том же стиле, что и светлая (насыщенный зелёный, видимое фото, мягкие поля). Чтобы вернуть прежнюю тёмную тему, удалите этот файл и его `<link>` в index.html.
- `js/mobile.js` + `mobile.css` — мобильный слой: нижняя панель **Главная / Культуры / Карта GIS** (на экранах ≤ 820 px) и раскрывающаяся карточка региона. На компьютере (> 820 px) вид сайта не меняется.

Идентификатор приложения: `com.agrisupport.app`. Версия: 0.2.1 (versionCode 21).

## Сборка (Android Studio)
1. Откройте папку проекта, дождитесь «Gradle sync» (нужен интернет; JDK 17 или 21 из Android Studio, SDK 35).
2. Выберите `app` и телефон (USB-отладка) или эмулятор, нажмите ▶.
3. Debug APK: **Build → Build Bundle(s) / APK(s) → Build APK(s)** → `app/build/outputs/apk/debug/app-debug.apk`.
4. Release: **Build → Generate Signed App Bundle / APK** (создайте ключ в мастере, сохраните его и пароль в надёжном месте).
Установка APK на телефон: отправьте `app-debug.apk` на телефон, откройте файл и разрешите установку из этого источника.

## Зависимости
Android Gradle Plugin 8.7.3, Gradle 8.9, Kotlin 2.0.21, androidx.core-ktx 1.15.0, appcompat 1.7.0, core-splashscreen 1.0.1. Права: INTERNET, ACCESS_NETWORK_STATE (больше ничего).
Сайт при работе берёт из интернета: плитки карты OpenStreetMap/Esri, Leaflet (unpkg.com), шрифт PT Sans (Google Fonts), границы стран/регионов (geoBoundaries), иллюстративные фото.

## Требования к серверу (API)
Сайт ожидает сервер `server.py` (в архиве сайта). Приложение работает и без него, но:
| Что | Без сервера | С сервером |
|---|---|---|
| Каталог культур, расчёты NPK/орошения, карта, темы, языки | работает | работает |
| NASA POWER, NOAA/NWS, USDA NRCS | «источник недоступен» | работает |
| Фото карточки и фона культур | не отображаются | отображаются |
| Загрузка фото администратором | недоступна | недоступна из приложения (запросы с телом не пересылаются) |
Чтобы подключить сервер, разместите `server.py` в интернете по HTTPS и впишите адрес в `gradle.properties`: `AGRISUPPORT_API_BASE=https://ваш-адрес` (без `/` в конце), затем пересоберите приложение.

## Что НЕ делает это приложение (и почему)
- **Регистрации и входа нет.** В сайте v0.2.1 нет учётных записей: он публичный, «только чтение» (в самом сайте написано «No accounts»). Есть только пароль администратора для загрузки фото. Я не стал придумывать отдельную систему входа, не связанную с сервером. Когда на сервере появятся пользователи, экраны входа можно добавить.
- **Выбор региона** сейчас один: Nebraska / UNL South Central Agricultural Laboratory (единственный регион в данных сайта). Данные не менялись и не придумывались.

## Проверка (что реально выполнено)
Выполнено в Chrome (эмуляция телефона) на ширинах 320, 360, 375, 390, 414, 430, 768 и 1280 px: старт, нижняя навигация, каталог (14 культур), поиск, карточка региона (сворачивание/разворачивание), страница культуры, вкладки «Земля» и «Данные», переход на карту и обратно, языки EN/RU/TJ, тёмная и светлая темы; горизонтальной прокрутки нет, ошибок JavaScript нет.
**НЕ выполнено** (в среде нет Android SDK и доступа к его серверам): компиляция Kotlin, сборка APK, запуск на эмуляторе/телефоне, проверка карты Leaflet с реальными плитками, поведение при отключении интернета на устройстве, кнопка «Назад» на устройстве. Эти пункты нужно проверить при первом запуске в Android Studio.


## Что нового в r7 (и r5, r6) (сайт AgroSupport v0.2.1, всё работает внутри приложения)
Сервер `server.py` в приложение не нужен: его расчёты перенесены в `app/src/main/assets/js/android-api.js`
(это Python-код сайта, переписанный на JavaScript один в один). Расчёты и данные:
- **Калькуляторы** (баланс удобрений NPK, текстовая сводка «ИИ») считаются прямо на телефоне, без интернета. Это шаблонный вывод по формулам, не языковая модель: ключей OpenAI в приложении нет, и сайт честно пишет «без модели».
- **Вкладка «Данные NASA»** (доказательства, Climate Twin, MODIS NDVI, сезонные показатели) берётся из настоящих сохранённых ответов NASA в папке `assets/data_snapshots/` (за 2025 год). Они помечены `snapshot` и датой получения. Ничего не придумано.
- **Прогноз NOAA, погода NASA POWER по любой точке и годовая климатика** — с телефона по интернету через встроенный прокси (`/__ext/`, разрешены только power.larc.nasa.gov, api.weather.gov, modis.ornl.gov). Если интернета нет, показываются сохранённые снимки или «источник недоступен».
- **Почвы USDA** — только сохранённый снимок (живой запрос там POST, через прокси не поддержан).
- **Загрузка фото и вход администратора отключены** (как в «cloud-demo» режиме сайта): в публичном приложении нет сервера, куда сохранять.
- **Страницы калькуляторов переведены на EN и TJ** (`tools/tools-i18n.js`): надписи, подсказки и сообщения следуют переключателю языка сайта. Формулы не менялись. Таджикский перевод сделан без носителя языка, его нужно вычитать.
- `AGRISUPPORT_API_BASE` в `gradle.properties` больше не нужен (можно оставить пустым).

## Как это проверено
- 45 сравнений JavaScript-версии с исходным Python-кодом (science.py, agro_calc.py, agro_lab.py, agro_nasa.py): все совпали, включая тексты ошибок. Скрипты проверки не входят в проект.
- Страницы и запросы к данным проверены в Chrome (ширина 360–768 px): ошибок JS нет, калькуляторы и вкладка NASA работают.
- **Не проверено** (в моей среде нет Android SDK и нет доступа к NASA): сборка в Android Studio, запуск на телефоне, живые запросы NASA/NOAA через прокси на Kotlin.
